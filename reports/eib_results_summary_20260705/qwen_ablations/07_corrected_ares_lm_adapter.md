# Corrected FOG LM-Adapter Result

This report contains the corrected FOG result obtained on 2026-07-21. Unlike the earlier EIB action-classification head, this implementation does not replace or bypass the language-model head. FOG conditions the frozen Qwen2.5-Omni decoder through four learned latent residual tokens, and the original frozen LM head autoregressively generates the structured action.

## Protocol and Integrity Audit

- Backbone: frozen Qwen2.5-Omni-7B Transformer, decoder, and LM head.
- Trainable component: FOG evidence projectors, query-conditioned stream weighting, deterministic bottleneck, and latent-token projection.
- Trainable parameters: `1,444,992` (`0.0162%` of the `8,931,813,888`-parameter Qwen thinker).
- Split: episode-disjoint train `1807` steps / dev `257` / test `508`, with `0` overlapping episodes.
- Checkpoint selection: minimum dev per-action teacher-forced NLL; test labels were not consulted.
- Test scope: all `508` held-out steps from `142` episodes; no missing, duplicate, or extra IDs.
- Evidence cache: all `2572` examples, extracted by a frozen Qwen forward without action labels, task categories, future states, or episode identifiers.
- Generation: all test actions were newly generated by the frozen Qwen decoder and original LM head conditioned on the trained FOG tokens.
- Legacy classification head used: `false`.
- Adapter checkpoint SHA-256: `4b5c7c858c7cf410ca144f2784b61584c7ac0eaaed76e75585016066aae9b4bc`.

## Training Selection

The final configuration was selected from a dev-only pilot. Deterministic gating achieved higher executable-action Exact than the tested VIB configuration (`0.1875` vs. `0.1406` on the 64-step pilot dev subset), so the strict run disables stochastic VIB and its KL term. The paper must therefore describe the evaluated final model as deterministic action-sufficient compression, not claim that VIB produced this result.

The strict run trained for three epochs on two GPUs. Dev action NLL decreased monotonically from `0.5519` to `0.5189` to `0.5053`; epoch 2 was selected before the test run.

## Evidence Selection Behavior

Mean held-out evidence weights are:

| Text/history | Screen | Audio | Video | State | Full-modal | Screen-spatial |
|---:|---:|---:|---:|---:|---:|---:|
| 0.1568 | 0.1264 | 0.1455 | 0.1261 | 0.1797 | 0.1921 | 0.0734 |

The weights vary with the interaction step. At step 0, state receives `0.3085` and full-modal evidence `0.1213`; by step 3, state falls to `0.0746`, while full-modal and audio rise to `0.2401` and `0.1842`. This is evidence of step-conditioned weighting, but it is not by itself a causal proof that every stream is useful. Stream occlusion or corruption experiments remain necessary for a strong causal evidence-selection claim.

## Interpretation Boundary

This run validates the architectural correction: FOG can improve held-out action generation while preserving the original autoregressive decoder and LM head. It is a parameter-efficient trained adapter, not a training-free method. The old EIB classification-head numbers are legacy diagnostic results and must not be reported as the final FOG method.

Two comparison boundaries must remain explicit in the paper. First, this is a custom supervised episode-disjoint protocol over OmniGUI, not the benchmark's zero-shot full-set leaderboard protocol; its numbers are directly comparable only to raw Qwen evaluated on the same 508 held-out IDs. Second, the current decoder-only implementation uses one frozen Qwen pass to construct evidence and another conditioned pass to generate the action. Cached evidence makes the reported benchmark run efficient, but a live agent would incur the two-pass backbone cost unless the implementation reuses intermediate states.
